# SEED 智能体与仿真器能力建设工作报告

近期工作的主线，是把 SEED Emulator 从“能够构建网络实验的仿真器”，推进为“能够被智能体持续观察、操作、验证和复盘的网络实验平台”。这项工作的价值在于：智能体可以面对一个已经运行起来的实验网络，根据真实运行状态分析问题，选择受控动作，完成验证，并留下可追溯证据。

目前结果比较乐观。我们已经形成了覆盖实验构建、运行时接入、智能体编排、安全约束、证据归档、网络控制面扩展和演示样例的一套体系。它支持智能体完成服务连通性排障、路径故障分析、路由状态检查、BGP 控制面操作、实验任务执行和运行结果总结，也开始支持更复杂的网络运维与科研实验流程。

![SEED 智能体总体架构](./generated_figures/final_architecture_4k.jpeg)

上图展示的是我们这轮工作的总体结构：底层是可运行的 SEED 网络实验环境，中间是运行时观测与受控动作平面，上层是智能体的目标理解、任务编排、策略控制和证据输出能力。整体目标是让智能体进入真实实验系统，围绕运行时事实完成闭环工作。

## 1. 工作重心

这轮工作覆盖面较广，但核心可以归纳为四件事。

第一，建立智能体操作 SEED 实验的运行时底座。智能体可以接入已经启动的实验网络，读取运行状态，理解节点、服务、路由和日志现象，并在权限边界内执行操作。

第二，把智能体行为纳入可审计闭环。智能体执行任务时，需要经历观察、判断、动作、验证、总结的流程。关键动作要有范围控制，高风险动作要有确认机制，任务结果要能追溯到运行证据。

第三，扩展 SEED 的网络控制面能力。我们围绕 BGP、FRR、ExaBGP 和 Looking Glass 做了系统性增强，使仿真器可以覆盖更接近真实网络运维和研究场景的控制面实验。

第四，建设可演示、可复现、可回归的实验样板。我们整理了从基础网络、服务网络、邮件/DNS、BGP、路由安全到智能体任务的多类样例，方便后续向老师、合作方和评审对象展示。

## 2. 系统架构

整体架构可以理解为四层。

| 层次 | 作用 | 本轮建设结果 |
| --- | --- | --- |
| 实验环境层 | 提供可运行、可复现的网络世界 | 保留 SEED 原有实验构建能力，补强 BGP、FRR、ExaBGP、Looking Glass 等控制面能力 |
| 运行时操作层 | 面向已经运行的网络提供观测和动作入口 | 支持接入运行态实验、读取状态、执行受控操作、采集证据 |
| 智能体编排层 | 把自然语言目标转成任务流程 | 支持规划、任务执行、策略门、确认门、失败回退和总结输出 |
| 验证与证据层 | 判断任务是否真正成功 | 支持前后对比、页面可达性验证、日志证据、路由证据和任务报告 |

这套结构的重点，是让智能体基于运行时事实工作。它看到的是实验网络当前实际状态，例如服务是否可达、路径是否中断、BGP 邻居是否稳定、路由表是否符合预期、页面是否能访问。它的动作也被约束在可记录、可验证、可回滚的范围内。

## 3. 智能体运行时能力

我们围绕“智能体如何真正操作一个运行中的仿真实验”做了完整工程化闭环。

智能体现在可以接入一个匿名运行时网络。它不依赖提前知道完整拓扑文件，也不把实验构建目录当作身份来源。它需要从运行状态出发，通过可允许的接口逐步建立判断。

智能体具备多类运行时感知能力，包括节点与服务识别、网络连通性检查、路由状态检查、BGP 状态检查、日志检查、页面可达性检查和任务证据汇总。

智能体具备受控执行能力，包括服务重启、故障注入与恢复、BGP 前缀宣告与撤销、运行时探测、任务验证和结果总结。高风险操作需要明确范围和验证步骤。

智能体具备交互式使用方式。命令式验证可以用于回归测试和批量验收，实际演示时可以通过交互方式与智能体对话，让它解释当前网络、拆解问题、执行操作并总结证据。

## 4. 约束与安全边界

这轮工作很重视“智能体不能假装全能”。原因很直接：如果智能体随意读取构建期信息、直接进入所有容器、任意执行命令，它的成功就无法说明真实智能水平，也无法形成可信演示。

我们明确了智能体的自我定位：它是运行时操作者，面对的是已经运行的实验系统。它优先使用结构化的观测和动作能力，通过运行时现象进行判断。容器级操作、底层命令和高风险动作都要受到策略约束。

我们补强了单运行时约束。任何时刻只允许一个主要实验 baseline 在线，避免多个网络同时运行造成端口冲突、网络命名冲突、证据混淆和演示误判。

我们补强了证据要求。任务完成后，需要说明看到了什么、做了什么、验证了什么、证据来自哪里。对外演示时，重点不只看最终结论，也看智能体的分析过程、工具选择、动作范围和验证质量。

## 5. BGP、FRR、ExaBGP 与 Looking Glass

BGP 控制面是这轮工作的重点之一。它的意义在于，BGP 场景更接近真实网络运维，能够测试智能体对复杂状态、协议行为、风险操作和回滚验证的理解能力。

FRR 方向上，我们把它作为与原有路由后端并列的控制面能力推进。目标是让仿真器可以从构建阶段生成真实可运行的 FRR 网络，而不依赖运行时临时修补。验证重点包括邻居建立、路由传播、下一跳解析、主机连通、路由策略和混合后端互通。

ExaBGP 方向上，我们把它作为可嵌入仿真器的 BGP 工具节点。它可以用于注入、撤销和观察 BGP 事件，适合做控制面实验、路由安全演练和事件驱动观测。

Looking Glass 方向上，我们建设了面向 BGP 状态可视化的观测入口。当前重点是稳定展示路由状态视角，并结合 ExaBGP 事件视角，让用户区分“当前路由表状态”和“控制面事件流”两类证据。

这些能力共同支撑三类更有价值的实验：BIRD 到 FRR 的迁移验证、外部 BGP 工具节点接入、BGP 路由状态与事件状态的对照观察。

## 6. 实验与演示覆盖

我们把实验样例整理成可用于演示和回归的多类 baseline。

| 类别 | 代表内容 | 展示价值 |
| --- | --- | --- |
| 基础网络 | mini internet、自治系统、主机连通 | 展示智能体如何在未知运行态中理解网络结构 |
| 服务网络 | DNS、邮件、Web、PKI、Anycast 等 | 展示智能体如何处理服务可达性和应用层故障 |
| 路由控制面 | BGP、FRR、MPLS、路由服务器 | 展示智能体如何分析协议状态和路径变化 |
| BGP 工具链 | ExaBGP、事件面板、Looking Glass | 展示控制面工具如何嵌入仿真器并被智能体使用 |
| 任务化演练 | 故障恢复、路由安全、服务排障、科研实验 | 展示智能体如何从目标出发完成闭环任务 |
| 可视化演示 | Internet map、页面检查、dashboard | 展示人可以直接观察网络状态和智能体结果 |

其中，基础网络用于验证智能体的泛化理解能力；服务网络用于验证现实运维问题；BGP 控制面用于验证复杂协议推理；可视化入口用于让现场演示更直观。

## 7. Kubernetes 与部署方向

我们也围绕更大规模和更复杂部署环境做了探索。Kubernetes 方向的价值在于：未来 SEED 实验不一定只运行在单机 Docker 环境中，也可以面向多节点、多资源池和更接近云原生基础设施的部署方式。

这一方向当前重点是明确部署抽象、实验生命周期、网络资源隔离、运行时观测入口和智能体接入方式。它为后续把 SEED 从本地实验平台扩展到更大规模实验平台提供基础。

## 8. 方法论

![SEED 智能体方法原则](./generated_figures/final_principle_4k.jpeg)

我们这轮工作沉淀出的核心方法，是把智能体能力拆成五个连续环节。

| 环节 | 含义 |
| --- | --- |
| 运行时感知 | 先确认当前系统真实状态 |
| 目标拆解 | 把用户目标拆成可验证的子问题 |
| 受控动作 | 动作必须有范围、风险和回滚思路 |
| 结果验证 | 操作后重新检查关键状态 |
| 证据归档 | 留下可回看、可复现、可审计的结果 |

这个方法对后续发展很重要。它让智能体从“给建议”走向“可监督地做事”，也让实验结果从“看起来成功”走向“有证据支撑”。

## 9. 当前结论

当前工作已经证明，SEED 可以承载智能体运行时实验。智能体可以进入已经运行的网络环境，围绕服务、路由、日志、页面和控制面状态进行分析与操作，并产出可追溯结果。

BGP/FRR/ExaBGP/Looking Glass 方向已经形成较清晰的技术主线。它们让 SEED 能覆盖更复杂、更接近真实网络的控制面实验，也让智能体可以面对更有挑战的网络运维任务。

实验样例和演示材料已经具备初步体系。后续可以围绕基础网络理解、服务故障恢复、BGP 控制面演练和可视化观测组织对外展示。

## 10. 后续工作

后续建议分三条线推进。

第一条线是智能体可靠性。继续提升规划稳定性、工具选择质量、任务总结质量和交互式演示体验，让智能体减少空泛建议，更多基于运行时证据采取行动。

第二条线是网络控制面完备性。继续强化 FRR、BGP 策略、ExaBGP 工具节点和 Looking Glass 观测体系，让它们成为可复用的仿真器基础能力。

第三条线是规模化与平台化。继续推进 Kubernetes、多节点部署、实验 catalog、任务评测集和可视化 dashboard，使 SEED 智能体体系从实验样板发展为稳定平台。

## 11. 一句话总结

这轮工作的核心成果，是把 SEED Emulator 推进成了一个面向智能体的运行时实验平台雏形：它能构建真实网络实验，能让智能体进入运行态系统，能执行受控操作，能验证结果，能沉淀证据，并已经开始覆盖复杂 BGP 控制面和网络运维场景。
